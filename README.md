# Скилл-сканер (Skill-scanner)

**Скилл-сканер** — веб-приложение для сканирования списков навыков/инструментов ИИ-агентов и поиска **вредоносных действий** и **скрытых инструментов**, которыми можно манипулировать агентом.

Вставьте определение инструмента, MCP-конфига, набора промптов или манифеста расширения — и получите оценку риска **0–100** со списком находок и **цитатами-доказательствами**: каждая находка показывает точный фрагмент текста, который её вызвал.

---

## Возможности (версия 1)

- **Сканирование списка навыков** — вставьте манифест/определение и запустите анализ. Ничего не выполняется: только статический разбор текста.
- **Список оценок риска** — главный экран: навыки ранжируются от самых опасных к самым безопасным.
  - Оценка **0–100** и уровень: `Чисто` / `Низкий` / `Средний` / `Высокий` / `Критический`
  - Раскрывающиеся находки с описанием правила, весом и цитатами-доказательствами
  - Фильтры «Все / Высокий риск / Чистые» и сводка (всего / с риском / чистые / максимальный балл)
- **Интерфейс на двух языках** — переключатель **EN/RU**; выбор запоминается, язык определяется автоматически по браузеру. Переводятся и описания правил — уже сохранённые сканы тоже переводятся «на лету».
- **Экспорт отчёта в Markdown** — кнопка в раскрытой карточке навыка скачивает полный отчёт: оценка, тип, находки с весами и цитаты-доказательства. Язык отчёта берётся из интерфейса.
- **Личный воркспейс** — каждый скан хранится в Convex и доступен только вам (single-user по задумке v1).

## Что ищет детектор

10 правил (`src/convex/analyzer.ts`), заточенных под злоупотребления агентами:

| Категория | Примеры паттернов |
|---|---|
| Обфускация | `base64 -d \| sh`, hex-блобы, `eval(atob(...))` |
| Эксфильтрация | `curl -X POST` наружу, сбор `process.env`, доступ к `~/.ssh`, `id_rsa` |
| Перехват инструкций | «ignore previous instructions», скрытые системные промпты, «не говори пользователю» — распознаются **и английские, и русские формулировки** |
| Скрытые инструменты | shadow-серверы в `mcpServers`, `allowedTools: ["*"]`, авто-подтверждение |
| Закрепление | `crontab`, правки `~/.bashrc`, `LaunchAgents`, автозагрузка |
| Эскалация | `sudo`, setuid, `unshare`, `/etc/shadow` |
| Прочее | тихая установка пакетов (`curl … \| sh`), широкие обходы ФС, длинные закодированные блобы |

Оценка считается так: берётся максимальный вес сработавшего правила + бонус за каждую дополнительную категорию (максимум +24), итог обрезается до 100. Так навык, «шумит» по мелочи в нескольких местах, всё равно поднимается в списке.

## Технологии

- **Vite + React 19 + TypeScript** (роутинг на React Router v7)
- **Tailwind CSS v4** + shadcn/ui, шрифты Inter и JetBrains Mono
- **Convex** — база данных, бэкенд и аутентификация (email-код + гостевой вход)
- **Framer Motion** — анимации

## Структура проекта

```
src/
├── convex/
│   ├── analyzer.ts        # движок правил: 10 детекторов + подсчёт оценки
│   ├── skills.ts          # query/mutations: submitSkill, listMySkills, removeSkill
│   └── schema.ts          # таблица scannedSkills
├── lib/
│   ├── i18n.tsx           # LanguageProvider + словари EN/RU
│   └── rule-catalog.ts    # названия и описания правил на двух языках
├── components/            # DashboardHeader, LanguageSwitcher, ui/*
└── pages/
    ├── Landing.tsx        # лендинг
    ├── Auth.tsx           # вход (email-код или гость)
    └── Dashboard.tsx      # главный экран: сканер + список оценок риска
```

## Запуск локально

Нужен [Bun](https://bun.sh).

```bash
bun install
bun convex dev --once   # применить схему и сгенерировать типы
bun tsc -b --noEmit     # проверить типы
bun run dev             # dev-сервер Vite
```

Переменные окружения (`CONVEX_DEPLOYMENT`, `VITE_CONVEX_URL`) уже настроены в среде Freebuff; при локальном запуске подключите свой Convex-деплой (`bun convex dev`).

## Методика анализа (плейбук и протокол)

Ручной анализ по сканеру ведётся по формализованному плейбуку: 16 шагов с ветками «если → то» и стоп-флагами — [`docs/analysis-playbook.md`](docs/analysis-playbook.md), визуальная блок-схема — [`docs/playbook-flowchart.html`](docs/playbook-flowchart.html) (открывается офлайн в браузере).

Результат оценки фиксируется протоколом — модель скоринга, шкала вердиктов, заполненный живой пример и пустой шаблон: [`docs/skill-assessment-protocol.md`](docs/skill-assessment-protocol.md).

Кратко: **Подготовка (источник → паспорт → поверхность атаки) → Автоскан (оценка + разбор находок) → Ручной проход (10 чек-листов: обфускация, эксфильтрация, инъекции, shadow-инструменты, persistence, эскалация, установки, ФС, сеть, комбинаторика) → Вердикт + протокол**. Обновление навыка (новый хэш) = анализ заново.

## Самооценка сканера (SCANNER-SCORE.md)

Сканер прогнали через него самого — исходный код оценён по собственной методике: [`scores/SCANNER-SCORE.md`](scores/SCANNER-SCORE.md) (копия в [`assets/SCANNER-SCORE.md`](assets/SCANNER-SCORE.md)).

Файл содержит **пример оценки безопасности скилла по критериям детектора**: итоговый скор с разбивкой (база + бонус = итог), таблицу сработавших правил с весами и цитатами-доказательствами, ручной разбор каждой находки и вердикт.

Забавный и показательный результат: детектор выдал **100/100 «Критический»** — он нашёл в собственных исходниках паттерны инъекций, sudo, crontab и base64-блобы (это же таблица сигнатур и source map!). Все 6 находок разобраны как ложные срабатывания — наглядная демонстрация принципа «находка — сигнал, а не приговор».

Этот файл — эталонный образец того, как выглядит заполненный протокол оценки. Протокол для любого скана генерируется кнопкой «Скачать протокол» в Dashboard (итоговый скор — в шапке документа).

## Конфигурация: env рядом с проектом

Принцип проекта: **вся конфигурация живёт в env-файлах рядом с кодом**, ничего не хардкодится:

- **`.env.local`** — рабочий конфиг (`VITE_CONVEX_URL`, `CONVEX_DEPLOYMENT`, секреты). В git не попадает (`.gitignore`).
- **`.env.example`** — шаблон со всеми переменными, включая полный блок калибровки риска `RISK_*`.
- **`.env.keys`** — приватный ключ dotenvx для расшифровки зашифрованных значений (подход Freebuff).

Как это применяется:
- `bun x convex dev` **автоматически синкает** переменные из `.env.local` на деплой — достаточно дописать `RISK_STACK_BONUS_PER_RULE=10` в файл, и калибровка подхватится.
- Ручной способ: `bun x convex env set RISK_SCORE_CAP 90` (или через дашборд Convex).
- На фронте (`import.meta.env`) доступны только `VITE_*`-переменные.

Так развёртывание остаётся воспроизводимым: новый разработчик копирует `.env.example` → заполняет `.env.local` → всё работает.

## Методика для агентов (skill)

Методика упакована как **скилл для ИИ-агентов**: [`.claude/skills/skill-security-audit/SKILL.md`](.claude/skills/skill-security-audit/SKILL.md). Установи его в свой агент (Claude Code и совместимые) — и он сможет проводить аудит навыков по нашему плейбуку: статический анализ, 10 категорий проверки, стоп-флаги, оценка 0–100 и протокол `SCANNER-SCORE.md` с цитатами-доказательствами.

## Оценки и ограничения

- **Только статический анализ** — находки это *сигналы, а не приговоры*. Всегда проверяйте вручную: возможны ложные срабатывания (например, легитимный `curl` в скрипте сборки).
- Правила ищут паттерны в командах и промптах на английском **и русском**; другие языки (пока) не покрываются.
- Доказательства (цитаты) не переводятся намеренно — это исходный текст манифеста.
